# 09 · AI-аналитик водоёма (RAG)

Модуль `js/ai-analyst.js`. По выбранной на карте точке он отвечает на вопрос: **какая рыба здесь реально водится и с какой уверенностью** — опираясь на реальные факты о водоёме (OpenStreetMap) и научную базу по экологии видов (`fishdb.js`).

## Зачем

Тип водоёма из карты — это ещё не список рыб. OSM почти никогда не содержит ихтиофауну. Поэтому аналитик действует как ихтиолог: берёт измеримые признаки места (тип, размер, связь с рекой, камыш, кислородный режим малой воды) и сопоставляет их с экологией каждого вида. Если данных о водоёме мало — честно переходит к оценке «по аналогии» (тип + ареал + размер) и помечает это.

## RAG-пайплайн

Архитектура намеренно построена как Retrieval-Augmented Generation, чтобы позже бесшовно подключить Claude:

1. **Retrieval** — `assembleContext()` собирает факты о точке из `profileWater()` (OSM): тип, площадь/ширина, размерный класс, связь с рекой и притоки, камыш, мост, острова, изрезанность берега, качество данных.
2. **Reasoning/Augment** — `plausibility(id, P)` для каждого вида считает правдоподобие обитания, а `buildClaudePrompt()` собирает промпт из фактов + знаниевых карточек `KNOWLEDGE` (корпус) по видам-кандидатам.
3. **Generation** — два провайдера:
   - `local` (работает сейчас): детерминированный экспертный синтез — ранжирование видов с обоснованием, доказательствами и уверенностью.
   - `claude` (заглушка): отправка промпта на бэкенд `/api/ai/analyze`, где Claude через CLI возвращает строгий JSON.

`analyzeWater()` выбирает провайдер из `AI_CONFIG.provider`; при сбое Claude-бэкенда откатывается на `local`, поэтому сайт **всегда** выдаёт результат.

## Логика правдоподобия (local)

База: `FISHES[id].waters[тип] × latPresence(вид, широта)`. Далее множители по реальным факторам:

| Фактор | Правило |
|---|---|
| Связь с рекой | вид с `riverLink ≥ 0.6` в изолированном водоёме (`connectivity ≤ 0.3`) → ×0.16 («нужен выход в реку»); при связи → ×1.18 |
| Изолированный пруд | «прудовые» виды (`riverLink ≤ 0.2`) при отсутствии связи → ×1.08 |
| Размер | в очень малом водоёме крупные/хищные → ×0.3; мелкие нехищные → ×1.12 |
| Кислород | в малой изолированной воде `o2:"high"` → ×0.45 (риск замора), `o2:"low"` → ×1.2 |
| Камыш | вид-фитофил при наличии тростника → ×1.1 |
| Зарыбление | карп/амур/толстолобик только в прудах/водохранилищах, иначе ×0.15 |

Итог 0..1 → классы обоснования: `typical` (типичный вид), `likely` (вероятен), `possible` (возможен). Виды с уверенностью < 8% не показываются.

Эта же уверенность передаётся в `engine.computeBite` как оценка присутствия и управляет «потолком честности» итогового шанса клёва — то есть AI-разбор напрямую влияет на прогноз.

## Подключение Claude через CLI (следующий шаг)

Фронтенд уже готов; нужен тонкий бэкенд-прокси:

```
POST /api/ai/analyze
  body: { model, prompt, context }
  → сервер вызывает Claude CLI:  claude -p "<prompt>" --output-format json
  → парсит { summary, species:[{name,confidence,rationale,evidence[]}], notes[] }
  → возвращает фронтенду
```

Рекомендации: кэшировать ответы по округлённым координатам+месяцу (RAG-факты меняются медленно), ограничить запросы (rate-limit, см. 07), не передавать точные координаты в внешние логи. Переключение — одна строка: `AI_CONFIG.provider = "claude"`.

Корпус знаний для RAG — `KNOWLEDGE` в `fishdb.js`; источники — `SOURCES`.
