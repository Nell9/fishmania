# 05 · Алгоритмы

## 1. Температура воды (`weather.js: estimateWaterTemp`)

Вода — тепловой аккумулятор: следует за воздухом с запаздыванием. Берём почасовую T воздуха за 7 прошлых дней и считаем экспоненциальное сглаживание:

```
ema += α · (T_air − ema),   α = 1 / (tau · 24)
```

`tau` (сутки) зависит от водоёма: пруд 2.5, старица 3, малая река 3, канал 4, крупная река 5, озеро 6, водохранилище 7.

Поправки: солнечный прогрев мелких водоёмов в апреле–сентябре (до +1.5 °C при малой облачности, через `sun`-фактор водоёма); течение −0.6 °C летом (>20 °C); клампы 0.2…30 °C.

**Точность ±2 °C** — это честная оценка, в UI всегда помечена «модель». Тот же EMA-ряд строит график «вода и воздух, 7 дней».

## 2. Фаза Луны (`astro.js`)

Синодический расчёт от эталонного новолуния 2000-01-06 18:14 UTC, период 29.530588853 сут. `frac` 0..1 → название, освещённость `((1−cos 2πf)/2)`, иконка. Влияние на клёв мягкое: полнолуние 0.82, новолуние 0.88, растущая до 1.0, убывающая 0.9.

## 3. Восход/закат (`astro.js: sunTimes`)

Упрощённый NOAA-алгоритм (юлианский день → уравнение времени → часовой угол при −0.83°). Точность ±5 мин, используется как фолбэк — основной источник `daily.sunrise/sunset` из API. Обрабатывает полярные день/ночь.

## 4. Шанс клёва (`engine.js: computeBite`)

Взвешенная сумма 9 факторов (каждый 0..1):

| Фактор | Вес | Как считается |
|---|---|---|
| Сезон | .18 | `months[месяц]` со сдвигом по широте: `(lat−55)·0.06` мес (юг — раньше, север — позже) |
| Водоём | .13 | `waters[тип] × latPresence` (плавный спад за ареалом ±3°) |
| T воды | .16 | трапеция по `temp[4]` вида |
| Время суток | .12 | `times[период]`, период от восхода/заката (зорька = ±1.2…1.8 ч) |
| Давление | .14 | тренд за 24 ч: стабильно 1 → резко падает 0.45 / резко растёт 0.5; экстремумы <728 и >778 мм ×0.8 |
| Ветер | .09 | 1.5–5 м/с = 1 (рябь — идеал), штиль 0.72, >12 м/с 0.25; С/В ×0.85, Ю/З ×1.05 |
| Небо | .08 | тёплая вода: пасмурно лучше; холодная: ясность; ливень ×0.35, летняя морось ×1.05 |
| Луна | .05 | см. п.2 |
| Насадка | .05 | балл лучшей доступной насадки (п.6) |

**Ограничитель честности:** при `waters×latPresence < 0.15` итог ≤14% («не та рыба для этого места»), при <0.35 — ≤45%. Итог клампится 3..96%.

## 5. Почасовой прогноз (24 ч)

Та же формула по каждому часу прогноза: время суток (вес ↑ 0.30), давление/ветер/небо — из почасовых рядов, сезон/T/Луна — константы дня. Восход/закат берутся для конкретной даты часа. На графике подсвечиваются зорьки.

## 6. Ранжирование насадок (`engine.js: rankBaits`)

База — `fish.baits[id]`, далее множители:

- T воды <11°: animal ×1.3, plant ×0.55, live ×1.15, быстрые железки ×0.8, джиг ×1.15;
- T воды >18°: plant ×1.18, animal ×0.85;
- несовместимость со снастью ×0.15 (показывается отдельно с пометкой);
- насадка есть у рыбака ×1.12 (лёгкий приоритет при прочих равных).

## 7. Тактика (`engine.js: buildTactics`)

Сборка текстовых блоков из правил: место (пересечение `habitat` рыбы и отмеченных ориентиров + проверка глубины), лучшие 3 часа из почасового прогноза, прикормка (тяжёлая на течении, минимум в холодной воде), подача по снасти (включая медленную ступеньку при холодной воде), поправка на ветер (прибойный берег летом / затишье в холод) и давление. При шансе <30% — честный совет сменить цель (через `adviseFish`).

## 8. Подбор схем точек (`spotmaps.js: selectSpots`)

9 шаблонов (кромка камыша, окно в кувшинках, бровка, коряжник, поворот-омут, перекат-яма, бровка канала, опоры моста, дамба). Фильтр по типу водоёма, далее счёт: +2 за совпадение тега с `habitat` рыбы, +1.6 за отмеченный рыбаком ориентир, +0.8 за соответствие глубинных предпочтений. Топ-3 рендерятся с дистанцией заброса по снасти; у глубинных схем — профиль дна (вид сбоку) с точкой оснастки.
